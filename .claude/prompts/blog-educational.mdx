**Goal:** Generate one new educational blog post for agentcenter.cloud — a practical how-to or guide that teaches developers and teams how to do a specific thing with AI agents or the AgentCenter platform.

**Repo:** https://github.com/MissionControlSquad/website.git
**Branch:** main
**Post date timezone:** Asia/Kolkata (IST) — use current date in IST

---

### Step 0 — Environment Setup

Run these commands before anything else:

```bash
git config --global user.email "bot@agentcenter.cloud"
git config --global user.name "AgentCenter Blog Bot"
gh auth setup-git
```

This sets git identity and authenticates the `gh` CLI using the `GITHUB_TOKEN` environment variable. Required for `git push` and `gh pr create` to work. If `GITHUB_TOKEN` is not set, stop and report the error.

### Step 2 — Pick a Topic

**Before picking:** run `ls content/blog/`, scan filenames, and cross-check the existing posts table in `blog.md`. Only pick a topic with no existing coverage — including partial coverage where the core angle is already taken.

Choose ONE topic from this list:

How to set up agent monitoring from scratch, How to debug a failing AI agent in production, How to roll back an AI agent safely, How to write an agent runbook your team will actually use, How to track agent costs per task, How to handle agent rate limits at scale, How to version AI agent prompts like code, How to alert on agent drift without drowning in noise, How to pass context between agents in a multi-agent pipeline, How to test an AI agent before shipping it, How to review agent deliverables at scale, How to structure a Kanban board for AI agents, How to use @mentions to coordinate agent work, How to measure AI agent ROI, How to detect when an agent is stuck or looping, How to migrate from DIY agent management to a dedicated platform, How to set up approval workflows for agent outputs, How to onboard a new AI agent into an existing workflow, How to run a post-mortem on an agent failure, How to decide how many agents your team actually needs, How to manage agent credentials and secrets safely, How to use recurring tasks for always-on agent workflows, How to build a cost dashboard for your AI agents, How to reduce LLM token costs without changing agent behavior

If all are taken, generate a new practical how-to for developers managing AI agents in production that isn't listed above.

**Date:** Use yesterday's date in IST (current date minus 1 day). Same-day posts are allowed — no minimum spacing between posts. The only requirement is that no two posts share the exact same timestamp.

---

### Step 3 — Write the Post

Follow **Type B — Educational / How-To Post** structure from `.claude/commands/blog.md` exactly:

- Direct opening (state the problem, no fluff)
- The concept explained plainly
- Step-by-step numbered sections
- Real example using a specific AgentCenter feature or workflow
- Common mistakes or misconceptions
- Bottom line
- CTA (see `.claude/commands/blog.md` for educational CTA format)

**Word count:** 700–1300 words. Do not exceed 1300.

Include at least one Mermaid diagram illustrating the process or workflow described. Use `<br/>` for line breaks inside labels — never `\n`.

**Tags:** Use proven tag patterns from `blog.md`. Always include `best-practices` or `how-to` and `ai-agents`. Max 5 tags total.

**Date field:** Use **yesterday's date** in IST (current date minus 1 day) with the fixed Type B slot `T06:00:00+05:30`. Format: `YYYY-MM-DDTHH:MM:00+05:30`. Example: if today is 2026-05-01, use `"2026-04-30T06:00:00+05:30"`. Never use today's date or a future date. Verify it is not already used by another post.

**Filename:** `content/blog/[how-to-slug].mdx`

Run the SEO checklist from `blog.md` before saving.

---

### Step 4 — Branch, Commit & PR

1. Write the MDX file to `content/blog/[slug].mdx`
2. Update `public/llms.txt` — append to the end of the `## Blog` section (before `## Legal`):
   `- [Post Title](https://agentcenter.cloud/blogs/[slug]): One-line description of what the post covers.`
   Also increment the post count in the Blog Index line (e.g. `39 posts` → `40 posts`).
3. `git checkout -b blog/edu-[slug]`
4. `git add content/blog/[slug].mdx public/llms.txt`
5. `git commit -m "blog: add educational post — [topic]"`
6. `git push origin blog/edu-[slug]`
7. Open a PR from `blog/edu-[slug]` → `main` with title: `blog: [topic]`
8. **Do NOT merge the PR.** Leave it open for the site owner to review and merge.
