### Step 3 — Write the Post

Follow **Type D — Perspective / Lessons Learned Post** structure from `.claude/commands/blog.md` exactly:

- Scene-setting opener (specific, grounded — real numbers, real situation, not generic)
- The shift or realization
- Concrete examples (specific failure modes, specific features, real numbers where possible)
- What the reader should take away (a decision, a habit, a frame — not a product pitch)
- Who this matters most for (role + specific situation)
- Honest caveat — don't oversell AgentCenter or AI agents generally
- CTA (see `.claude/commands/blog.md` for perspective CTA format)

**Word count:** 700–1300 words. Do not exceed 1300.

Include at least one Mermaid diagram illustrating the failure mode, pattern, or concept being discussed. Use `<br/>` for line breaks inside labels — never `\n`.

**Tags:** Use proven tag patterns from `blog.md`. Always include `production` or `best-practices` or `observability` and `ai-agents`. Max 5 tags total.

**Date field:** Use **yesterday's date** in IST (current date minus 1 day) with the fixed Type D slot `T18:00:00+05:30`. Format: `YYYY-MM-DDTHH:MM:00+05:30`. Example: if today is 2026-05-01, use `"2026-04-30T18:00:00+05:30"`. Never use today's date or a future date. Verify it is not already used by another post.

**Filename:** `content/blog/[topic-slug].mdx`

Run the SEO checklist from `blog.md` before saving.

---

### Step 4 — Branch, Commit & PR

1. Write the MDX file to `content/blog/[slug].mdx`
2. Update `public/llms.txt` — append to the end of the `## Blog` section (before `## Legal`):
   `- [Post Title](https://agentcenter.cloud/blogs/[slug]): One-line description of what the post covers.`
   Also increment the post count in the Blog Index line (e.g. `39 posts` → `40 posts`).
3. `git checkout -b blog/perspective-[slug]`
4. `git add content/blog/[slug].mdx public/llms.txt`
5. `git commit -m "blog: add perspective post — [topic]"`
6. `git push origin blog/perspective-[slug]`
7. Open a PR from `blog/perspective-[slug]` → `main` with title: `blog: [topic]`
8. **Do NOT merge the PR.** Leave it open for the site owner to review and merge.
